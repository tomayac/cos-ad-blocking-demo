Ad blocking and Cross-Origin Storage

A publisher page loads Prebid.js, a header-bidding library that content blockers block, in four ways. The companion extension blocks it by its URL and by its Cross-Origin Storage hash.

  1. Warm Cross-Origin Storage

    Load Prebid.js from jsDelivr with integrity and crossoriginstorage. On a miss, the browser fetches it and stores the verified bytes. Run this with the extension's rules off, as a page would on a browser without a content blocker. 

    <script src="https://cdn.jsdelivr.net/npm/prebid.js@11.40.0/…/prebid.js"
        integrity="sha384-…" crossorigin="anonymous" crossoriginstorage>

  2. Load it again: a Cross-Origin Storage hit

    The same tag again. The bytes now come from Cross-Origin Storage, with no network request, so no URL rule sees one. The hash rule keeps the file from being served from there, and the URL rule then blocks the network request that follows.

  3. Load it under a renamed first-party URL

    A publisher evades filter lists by serving the library from an innocuous path on its own site. Here, vendor/a7f3c9.js does not even exist: only Cross-Origin Storage can answer, by the hash in integrity. No URL rule matches, so only the hash rule catches it. 

    <script src="vendor/a7f3c9.js" integrity="sha384-…"
        crossoriginstorage>

  4. Load it with no URL at all

    Script reads the bytes with navigator.crossOriginStorage.getFileHandle() and runs them from a blob: URL. There is no request to match, so only the hash rule catches it. 

    const handle = await navigator.crossOriginStorage.getFileHandle(
    {algorithm: 'SHA-384', value: '…'});
script.src = URL.createObjectURL(await handle.getFile());

Needs a Chromium build with Cross-Origin Storage, started with --enable-features=CrossOriginStorage, and the COS Ad Blocker extension loaded unpacked. Source and instructions.
